## R8 游戏内直接开房

**前置条件**
- A、B 两台；A 已开房（默认 7790），B 已加入同一局（R1 通过）；A「游戏内控制」= 已允许。
- 记下 A 的房间码与 `grep -c 'Command mp.host completed'` 的基线值。

**步骤**
1. A 记录房间码与端口；执行 `snap R8-a`。
2. A 在游戏内停房 → 地址改 `127.0.0.1:7790` → 在游戏内建房（**不要点 Cuprum 的任何按钮**）。
3. ≤10 秒 Cuprum 应识别「游戏内已开房。」、把隧道对账到 7790、显示「房主 · 游戏端口 7790（自动检测）」与地址 `10.144.144.1:7790`；执行 `snap R8-b`。
4. 统计 mp.host 次数：`grep -c 'Command mp.host completed'` 相对步骤 1 的增量应为 0；执行 `snap R8-c`。
5. B 侧记录连接状态文案（隧道换端口后 B 可能回「等待玩家加入」或出现「房主已换房…」/「房主已离开…」，按 R11 判定，这里只记录）。

**预期**
- 房间卡/游戏卡显示房主、地址 `10.144.144.1:7790`、来源「自动检测」。
- Cuprum 不重复开房（mp.host 增量 0），游戏内房间不被拆掉。
- 活动日志出现 `The game moved to port 7790; room … follows it.` 与界面提示「游戏已换到端口 7790。」。

**失败判据**
- 又下发了一次 mp.host（增量 ≥1），或游戏被 Cuprum 重启到别的端口。
- 端口没对账：地址仍是旧端口，或活动日志没有 moved/follows 行。
- Cuprum 报错、游戏内房间被拆。
- 界面显示「游戏内已开房。」但端口/地址为空。

**证据文件**
- `$EVID/R8-a/`…`R8-d/`；mp.host 次数对比写在报告里（两个数字）。

**原始注入命令**
无注入（游戏内 UI 建房）；取证：

```bash
snap R8-b
grep -c 'Command mp.host completed' "$CUPRUM_DATA/Logs/"Log*.log
grep -a 'moved to port\|follows it' "$CUPRUM_DATA/Logs/"Log*.log | tail -3
ss -lunp | grep 7790
```
