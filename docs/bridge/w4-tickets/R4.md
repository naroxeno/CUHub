## R4 QuickTest 失败注入（4 组，各一次）

**前置条件**
- A 单机；R3 已把「游戏内控制」设为「已允许」；游戏能进主菜单；A 已能正常开房（R1 通过）。
- 每组注入前都先退出游戏（`pgrep -af Casualties` 空），恢复后再跑下一组，避免状态叠加。

**R4-a 缺 CUCoreLib.dll → unavailable**

**步骤**
1. 退出游戏与 Cuhub；按 [commands.md](commands.md) I4 移走 `CUCoreLib.dll`。
2. 启动游戏到主菜单 → 启动 Cuhub → 打开「联机」页；执行 `snap R4a-a`。
3. 记录桥卡标志行与游戏卡状态文案；确认「在游戏内开房」按钮是否还在。
4. 退出游戏，按 [commands.md](commands.md) I4 恢复 dll，重启游戏确认恢复正常。

**预期**
- 桥卡标志从「是/否」退化为「—」（`mp.state` 失败，界面拿不到数据）；控制行仍是「已允许」。
- 游戏卡状态「游戏内联机不可用。」；没有开房/加入按钮；页面不崩。
- 恢复 dll 并重开游戏后，≤30 秒桥标志恢复、游戏卡回到「可以开始在游戏内开房。」。

**失败判据**
- 界面仍显示「可用 是」「运行中 是」等与事实相反的标志。
- 依旧渲染「在游戏内开房」并能点出错误弹窗。
- 恢复 dll 并重开游戏后仍显示「游戏内联机不可用。」超过 30 秒。

**证据文件**
- `$EVID/R4a-a/`（含 bepinex-tail.txt；`grep -a 'CUCoreLib' $EVID/R4a-a/bepinex-tail.txt`）、`$EVID/R4a-b/`（恢复后）。

**原始注入命令**

```bash
# 注入：见 [commands.md](commands.md) I4 前两段（备份 + 改名 .disabled）
# 恢复：见 [commands.md](commands.md) I4 后一段
snap R4a-a
ls "$GAME/BepInEx/plugins" | grep -i cucorelib
```

**R4-b 端口被占 → 应用层端口占用 / 游戏侧 net_lnl_server_start_failed**

本组拆两步，因为两条失败路径的拦截层不同。

b1（应用侧拦截，真机必现）：让游戏不建房，A 的端口输入框填 25003，按 [commands.md](commands.md) I2 先占住 UDP 25003，再点「开房」。

1. 执行 I2（占住 25003）；`ss -lunp | grep 25003` 确认 python3 在列。
2. A 端口输入框填 `25003`；点「开房」；执行 `snap R4b-a`。
3. 观察界面：预期提示「端口 25003 已被占用。」（对应 `multiplayer.error_port_in_use`），房间卡不出现，连接状态保持「未连接」。
4. 释放 I2（Ctrl-C），再次点「开房」→ 正常开房（判据同 R1）；执行 `snap R4b-b`。

预期（b1）
- 被应用拦在本地：活动日志**没有** `Command mp.host failed`（也没 completed）。
- 文案是「端口 25003 已被占用。」，不是「游戏内控制失败：…」。

失败判据（b1）
- 出现 `Command mp.host failed`：说明应用没做占用检查，把冲突推给游戏。
- 房间卡出现但隧道立刻断（说明静默换号或状态错乱）。
- 释放端口后重开仍失败（说明上一次失败没回滚干净）。

b2（游戏侧 QuickTest 失败，用于看 `net_lnl_server_start_failed` 原文）：占住 25003 后，在**游戏内**用 127.0.0.1:25003 建房。

1. 保持 I2 占用。
2. 游戏内「打开多人联机模组菜单」→ 取消「使用 Steam」→ 地址填 `127.0.0.1:25003` →「启动主机」。
3. 执行 `snap R4b-c`，然后 `grep -a 'Status' $EVID/R4b-c/bepinex-tail.txt | tail -4`。
4. Cuhub 侧观察：游戏卡不应显示「游戏内已开房。」（游戏没起来），也不应显示错误的「端口已被占用」提示（那是应用侧文案）；执行 `snap R4b-d`。
5. 释放 I2，游戏内重新建房成功。

预期（b2）
- 游戏日志出现 `AddressAlreadyInUse` 与 `Status: LiteNetLib：服务器 NetManager.Start() 失败。`（[w4-regression.md](../w4-regression.md) §1.4/[w4-regression.md](../w4-regression.md) §1.8 原文）。
- Cuhub 不下发 mp.host、不误报，连接状态与游戏卡状态保持可用态。

失败判据（b2）
- 游戏日志里没有状态原文（说明 QuickTest 路径与 [w4-regression.md](../w4-regression.md) §1.8 实测不一致，需要重写这一条）。
- Cuhub 把游戏侧失败显示成「端口 N 已被占用。」（应用侧文案被误用）。

**证据文件**
- `$EVID/R4b-a`…`R4b-d/`；b2 的关键行在 `R4b-c/bepinex-tail.txt`。

**原始注入命令**

```bash
# b1/b2 前置：占住 25003（另一个终端，Ctrl-C 释放）
python3 -c 'import socket,sys,time;p=int(sys.argv[1]);s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM);s.bind(("0.0.0.0",p));print("holding udp",p,flush=True);time.sleep(900)' 25003
ss -lunp | grep 25003
# 游戏内菜单：取消「使用 Steam」→ 127.0.0.1:25003 → 启动主机
snap R4b-a
grep -a 'Command mp\.' "$CUHUB_DATA/Logs/"Log*.log 2>/dev/null | tail -5
```

**R4-c 玩家名称 <3 字符 → net_name_too_short**

**步骤**
1. 游戏内「打开多人联机模组菜单」→ 玩家名称改成 `ab`（2 字符）→ 关掉菜单。
2. 回 Cuhub，确认游戏卡「可以开始在游戏内开房。」；点「在游戏内开房」→「确认」；执行 `snap R4c-a`。
3. 观察错误文案与「重试」按钮；确认没有第二次自动尝试（房主侧一次性）；执行 `snap R4c-b`（10 秒后再抓一次）。
4. 游戏内把名称改回 ≥3 字符，再点「重试」→ 应成功开房。

**预期**
- 只尝试 1 次；界面出现「游戏会话不可用。」（桥把失败归为 unavailable）与「重试」按钮，不会自己反复重试。
- 活动日志出现 1 行 `Command mp.host failed:`，其后带游戏状态原文（应包含「玩家名称至少需要 3 个字符。」）。
- 名称改回 ≥3 字符后点「重试」成功，无需重启游戏或应用。

**失败判据**
- 连续自动重试（日志里多次 `Command mp.host failed`）。
- 界面文案与原因错配（例如显示「端口已被占用」）。
- 改正名称后必须重启游戏才能成功。

**证据文件**
- `$EVID/R4c-a`、`R4c-b/`；`grep -a 'Command mp.host failed' $EVID/R4c-a/cuhub-log.txt`；`grep -a 'Status' $EVID/R4c-a/bepinex-tail.txt`。

**原始注入命令**
名称只能在游戏内改，无 shell 注入；取证与确认：

```bash
snap R4c-a
grep -a 'Command mp.host failed' "$CUHUB_DATA/Logs/"Log*.log | tail -3
grep -a 'Status' "$GAME/BepInEx/LogOutput.log" | tail -4
```

**R4-d 非法地址（bad:notaport）→ net_invalid_ipport**

真机 UI 不可达：应用侧下发的地址恒为 `<ip>:<u16>`，端口输入框只收数字，非法端口在应用层就会被拦（`crates/app/src/ui/mp_control.rs:160-176`、`:62-92`），桥的 `invalid_params` 分支没有入口。本组改测「应用层非法端口」，桥侧 invalid_params 由 t9 的离线反射 harness（21 用例）覆盖，真机记录该缺口。

**步骤**
1. A 端口输入框依次填 `>65535`、`0`、`abc`（每改一次看提示）；执行 `snap R4d-a`。
2. 点「开房」→ 观察是否被拦、是否出现「端口要在 1 到 65535 之间。」；执行 `snap R4d-b`。
3. 改回合法端口（如 25003），正常开房确认恢复。

**预期**
- 非法输入被拦，出现「端口要在 1 到 65535 之间。」；活动日志没有 `Command mp.host`（没下发）。
- 合法值恢复后开房成功。

**失败判据**
- 非法端口被当成合法值下发（日志出现 `Command mp.host`），或 `0`/70000 被静默改成别的端口。
- 非法值导致应用 panic 或输入框卡死。

**证据文件**
- `$EVID/R4d-a`、`R4d-b/`；`grep -c 'Command mp\.host' $EVID/R4d-b/cuhub-log.txt`（期望 0）。

**原始注入命令**

```bash
# 无 shell 注入（UI 输入）；只取证
snap R4d-a
grep -aE 'port|Port' "$CUHUB_DATA/Logs/"Log*.log | tail -5
```
