## R10 房主退出后客人侧

**前置条件**
- A、B 两台；R1 已通过（A 在房、B 已进入同一局、两端「已连接」）。
- B 侧「游戏内控制」= 已允许（否则 B 不会自动动作，本用例失去意义）。

**步骤**
1. B 执行 `snap R10-a`，记录连接状态、地址行文案、`grep -c 'Command mp.join'` 基线。
2. A 在游戏内停房（或直接退出游戏，二者各测一次）；执行 `snap R10-b`。
3. B 等 ≤30 秒：应出现「房主已离开房间，等房主回来后可以重试。」（`multiplayer.game_host_left`），并且**自动重试停止**（10 秒内 mp.join 次数不再增加）；地址行消失；执行 `snap R10-c`。
4. 再等 30 秒确认没有反复重试、没有堆叠多条错误；执行 `snap R10-d`。
5. B 点「重试」一次（房主仍不在）→ 应只尝试一次并回到同样的提示，不进入无限重试；执行 `snap R10-e`。
6. A 回到房（重新开房，新码）→ B 用新码重进 → ≤60 秒「已连接」。

**预期**
- ≤30 秒出现「房主已离开房间，等房主回来后可以重试。」；自动动作停止（gate 关闭）。
- 地址行不再显示旧地址（连接状态不是「已连接」时不渲染地址）。
- 「重试」可用，且每次点击只尝试一次。
- 房主回来后用新码重进可以恢复正常。

**失败判据**
- 30 秒内没有任何提示，B 一直显示「已连接」或「等待玩家加入」。
- 提示出现但自动重试仍在继续（mp.join 次数持续增长）。
- 提示出现但地址行仍显示旧地址/旧端口。
- B 侧出现「游戏内控制失败：…」或需要重启 B 的 Cuprum 才能重试。
- 「重试」按钮点了没反应，或点一次触发多次尝试。

**证据文件**
- `$EVID/R10-a/`…`R10-e/`；`grep -c 'Command mp.join'` 在 R10-a 与 R10-d 的差值（期望 0）；`grep -a 'Left the room'`（A 侧）与 B 侧 `ui-b.png` 的提示文案。

**原始注入命令**
无状态注入；退出动作在 UI 里做。取证与计数：

```bash
snap R10-a
grep -c 'Command mp.join' "$CUPRUM_DATA/Logs/"Log*.log
snap R10-d
grep -c 'Command mp.join' "$CUPRUM_DATA/Logs/"Log*.log
```
