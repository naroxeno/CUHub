## R7 端口自动检测

**前置条件**
- A 单机；「游戏内控制」= 已允许；游戏在主菜单、未建房；端口输入框留空。

**步骤**
1. A 点「开房」（端口留空 → 隧道 7790）；执行 `snap R7-a`。
2. 游戏内建房：菜单 → 取消「使用 Steam」→ 地址 `127.0.0.1:7790` →「启动主机」；等 ≤10 秒让 Cuprum 对账；执行 `snap R7-b`。
3. 对照三处：房间卡端口行应为「房间端口 7790」；游戏卡第二行「房主 · 游戏端口 7790（自动检测）」；`ss -lunp | grep 7790` 里应是游戏进程（`Casualties`）。执行 `snap R7-c`。
4. 游戏内停房 → 地址改 `127.0.0.1:24444` →「启动主机」→ 等 ≤10 秒；重复第 3 步对照（`ss -lunp | grep 24444`）；执行 `snap R7-d`。
5. 游戏内停房（游戏不再上报端口）→ 端口输入框填 `25000`：端口行应显示「端口 25000 · 手动」；点「开房」→ 隧道按 25000 重建；游戏内用 `127.0.0.1:25000` 建房 → 当前房间显示「房间端口 25000」；执行 `snap R7-e`。

**预期**
- 7790、24444 两次都自动对齐：端口数字 = `ss -lunp` 中游戏进程的 UDP 端口，来源标「自动检测」。
- 游戏未上报端口时手填会标「手动」；游戏一上报就回到「自动检测」。
- 游戏在房且 Cuprum 尚未开房时，展开开房端口选项；手填与检测值不同，界面出现「端口填的是 X，但游戏实际在 Y。」与「采用检测端口」按钮（不是「手动」标签，见 D6）。
- 活动日志出现 `The game moved to port 24444; room … follows it.`。默认端口已是 7790，首次对齐不必重建。

**失败判据**
- 端口数字与 `ss -lunp` 中游戏进程的 UDP 端口不一致。
- 来源标签与实际不符（游戏已上报却显示「手动」/「默认」，或未上报却显示「自动检测」）。
- 改端口后隧道没跟随（活动日志没有 moved/follows 行），或跟随了但客人进不来。
- 手填不同值时没有 mismatch 警告。

**证据文件**
- `$EVID/R7-a/`…`R7-e/`；`grep -a 'moved to port\|follows it' $EVID/R7-d/cuprum-log.txt`；每拍 `ss-lunp.txt` 必须能和界面数字对上。

**原始注入命令**
无 shell 注入（游戏内 UI 改地址）；对照取证：

```bash
ss -lunp | grep -E ':7790|:24444|:25000'
ss -lunp | grep Casualties
snap R7-c
```
